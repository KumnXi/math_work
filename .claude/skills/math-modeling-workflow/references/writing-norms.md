# 论文写作与验收规范

写作前、写作中、验收前各读一遍。目标：**每个数值可溯源、每个断言有依据、格式一眼规范**。

## 一、数值一致性（证据门禁）

- 论文里出现的每个数值必须来自 `code/result_q*.json` 或附件，禁止手写/估计。
- 关键指标（目标值、误差、排名、权重、灵敏度）写进论文前，与 result JSON 逐项核对。
- 摘要的"结果段"用**最终版**数值；改过模型后重新跑代码，不要沿用旧数。
- 一致性是机器检查（验收 A3，±0.5% 容差）：数值没在正文出现或对不上 = 验收失败。

## 二、写作质量门禁（验收 A2/A7）

- 消灭占位符：`TODO`、`待补充`、`XX大学`、`队员X`、`placeholder`。
- 禁止内部文件泄漏：正文不得出现 `output/`、`result_q`、`run_manifest`、`task_state`、`_notes.md`、脚本名、`Mock`、`demo-cumcm` 等工作流痕迹。
- 要素齐全：模型假设、符号说明、灵敏度/稳定性分析、参考文献（GB/T 7714 真实文献）。
- 摘要独立页、五段式（背景→问题→方法→结果→结论），**必含具体数值结果**，正文中不出现公式。
- 图后必须有解释文字；公式后必须解释变量含义；结论不只报数还要说清"说明什么"。
- **论据充分**：每个判据/临界值/极值都有图表或迭代表支撑，不能只给一句话；迭代/扫描/二分过程用迭代表呈现，解答不跳跃（见 `benchmark-iteration.md` 第七节）。

## 三、题型防错速查

| 题型 | 易错点 | 应对 |
|---|---|---|
| 优化/规划 | 约束漏写、规模大硬解爆掉 | 列全约束；大规模用启发式（贪心+2-opt/CP-SAT），并说明近似性 |
| 预测 | 用错数据划分、未来值混入训练 | 严格按时间先后划分训练/测试；预测期用滚动方式 |
| 评价/决策 | 权重拍脑袋、量纲未归一 | 归一化后再综合；权重给出客观依据（熵权/层次/专家） |
| 分类/聚类 | 类别数拍脑袋、指标未标准化 | 用肘部法/轮廓系数定类别；标准化后再聚类 |
| 机理/方程 | 参数无来源、初值任意 | 参数来自题面或附件；初值敏感性做扰动说明 |

## 四、灵敏度与稳定性

- 对关键参数做 ±5%~±20% 扰动，说明结果是否稳健（有数值有结论，不能只说"稳健"）。
- 优化模型可说明目标函数对关键系数的敏感度；预测模型可说明对未来点预测的区间。

## 五、验收前自查（对照 `acceptance-checklist.md`）

- 图：`figures/check_report.json` 全 ok；`fig_pipeline.png` 存在；论文引用的图都过检。
- PDF：能编译、页数合理（**正文 ≤25，25~30 附论据说明，>30 精简；附录不计页**）、无空白页。
- 代码：`solve_q*.py` 可重跑、result JSON 与论文数值一致。
- 格式：公式编号、三线表、图引用完整、参考文献格式统一。
