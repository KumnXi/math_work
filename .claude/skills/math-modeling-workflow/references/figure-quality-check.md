# 数据图质量检查规范

跑完建模编程后会产生一批图，**能否进论文不能只看"生成出来了"**。出图后必须做两层检查：程序化检查（抓硬错误）+ 代码手审图（抓语义问题）。

## 一、能进论文的数据图标准

| 维度 | 标准 | 不达标示例 |
|---|---|---|
| 数据来源 | 数值必须来自 result JSON 或附件，可溯源 | 手写死数据、占位图 |
| 清晰度 | 宽≥600 高≥400 像素，300dpi，非纯色 | 模糊、过小 |
| 非空白 | 图中有实际内容（非白像素比例 >1%） | 全白/全黑/空坐标轴无数据 |
| 可读性 | 中文标题、坐标轴带单位、有图例/标注 | 乱码（□/方块）、无轴标签、无单位 |
| 风格 | 用 `figure_style.py`（统一配色 + 中文字体） | 风格突兀、默认英文配色 |
| 完整性 | 有对应结果解释、能独立看懂 | 只有孤零零一根线无说明 |
| 定位 | 数据图放结果/分析章节；流程图放问题分析/技术路线 | 数据图当流程图用 |

## 二、论证性图表（论据充分的硬要求，经验 2024-A）

数据图之外，每个**关键判据 / 临界值 / 极值**必须配一张论证图或迭代表，不能只给一句话结论（优秀论文全部如此）：

| 类型 | 画什么 | 数据来源 |
|---|---|---|
| 判据过零图 | 碰撞/可行性判据随参数或时间由负到正的零穿越 | result JSON 的判据曲线 |
| 极值/分布图 | 目标量沿时间/空间分布并标出极值点（先粗扫定位、窗口加密） | result JSON 极值 + 峰值窗口 |
| 收敛/迭代过程表/图 | 二分区间收缩、扫描步长加密收敛（区间宽度/步长 vs 迭代轮） | result JSON 迭代历史 |
| 效应/偏差图 | 近似模型 vs 精确模型的结果偏差（如固定弧长偏移 vs 刚体链，调头段压短 14%） | 对比求解结果 |

迭代表（三线表）同样算"图表证据"，数据来自求解器写出的迭代历史；这类图/表是 P5 "解答过程不跳跃"的载体。

## 三、检查流程（P4 阶段内置）

1. `make_figures.py` 运行成功。
2. 程序化检查：`$PYTHON_EXE tools/check_figures.py <figures_dir>`
   - 自动产出 `figures/check_report.json`，每张图记录 `ok / 尺寸 / ink_ratio / issues`。
   - exit≠0 说明有损坏/空白/过小图，必须修复后重跑。
3. 代码手审图：把 `check_report.json` + 求解结果给代码手，逐张核对数据来源、有无不可用图、能否直接进论文。
   - 无问题回复「全部可用」；有问题回复「需改进:」并逐条说明。
4. 审图结论写入 `team/coder_notes.md` 的『P4 审图结论』段，论文手 P5 据此决定用/不用。
5. 技术路线图 `fig_pipeline.png` 必须生成（问题分析章节引用），一并纳入检查。

## 三、常见坑

- **空图**：代码里变量算错导致空数组，`ax.plot([])` 只画个空坐标轴 → 程序化 ink 检查能抓住。
- **中文乱码**：未用 `figure_style` 或字体缺失 → 渲染成方块，审图时人工/LLM 检查标题文字。
- **坐标无单位**：图能看但论文没法用 → 审图要求坐标轴带单位。
- **数据与 result 不符**：图画的是另一套数 → 审图对照 result JSON 核对数量级。
- **图太多/太杂**：每个子问题 1-2 张核心图即可，宁精勿滥；论文正文 ≤25 页约束下图表总数可控。
